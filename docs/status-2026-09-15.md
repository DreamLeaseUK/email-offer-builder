- **Web app** (`apps/web`): Compose (URL lookup → term/mileage/initial **chips** that re-price in place → live preview iframe → create → Copy-for-Outlook + hosted link; **Save to library**), Campaigns (list + per-campaign stats), Library (saved offers, Add to campaign, delete), Register (master table + Export CSV). - **Promotions register** (`campaigns.ts`): `GET /api/register` (columns + rows JSON) and `GET /api/register.csv`, from one `registerRow()`.

## 5. Diagnostic findings (verified this session; persisted so they need not be re-derived)

- **Initial payment calculates correctly.** It is derived as `initial-months × monthly` (the site's endpoint returns 0 for it). Checked across vehicles, configs and both URL shapes (e.g. BYD Seal 12→£4,174 / 9→£3,318 / 6→£2,384; Frontera 6→£1,259). A "1-month" offer shows `initial == monthly` (e.g. £254 = 1×£254) — that is the **URL's own config** (an `offer=p-1-…` code / `initialRental=1`) or the **Initial "1 mo" chip**, *not* a bug. A bare paste defaults to the site's 12-month initial.
- **Black-background vehicle image is a local-dev artifact.** `wrangler dev`'s low-fidelity Images binding ignores the `background` fill (proven: requested magenta, still got black). The code correctly requests `#FFFFFF` (also the Cloudflare default), so **production renders the car on white**. The transparent car render is flattened to black only locally.
- **The site's vehicle-image host has moved** to `prodimages.cdn.motorcompleteplatform.co.uk` (was `images.motorleaseplatform.com`). The CAP-ID guard's `images.motorleaseplatform.com` pattern in `packages/schema/src/capid.ts` is now dead; the `capId` substring pattern still catches leaks, so the guard holds — but **consider adding the new host to `LEAK_PATTERNS` and the CI grep**. Identity and pricing still work (`window.motorleaseInit` is present on both `/offers/` and `…-car-lease-deals/` pages).
- **Local-dev URL/origin note.** In `wrangler dev`, `PUBLIC_BASE_URL` is the prod `workers.dev` origin, so image/hosted/link URLs are minted for prod while data is stored locally. The web app strips the origin for in-app display (works via the Vite proxy in dev, same-origin in prod); the Copy-for-Outlook HTML stays absolute (email needs it). So the tool preview shows local images, but an `.eml` opened in Outlook from a *local* lookup can't load the car photo (prod doesn't have that locally-stored file) — a local-testing limitation only; production is consistent.

## 6. Load-bearing constraints (unchanged, still enforced)

Per `CLAUDE.md`: **CAP IDs never stored** (`assertNoCapId` guards cache/brochure/library/campaign/rendered output; parser copies named fields only); **three layers, no leaks** (`render()` is the only HTML producer; no adapter imports another); **compliance locked** (a campaign can't render against an unapproved template; the seeded default template's wording is a **placeholder, not Emma-approved**); **drafts only** (the Worker never sends). The v5 markup non-negotiables (`docs/offer-mailer-implementation-notes.md`) still hold; after any `cards.ts`/`render.ts` change run `scripts/diff-reference.ts`.
