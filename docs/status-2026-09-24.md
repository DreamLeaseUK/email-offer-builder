## 10. Security hardening (Dev Coworker, branch `dev/security-hardening`, Matt's "yes")
The house starter template's ship check found three gaps that the Offer Mailer shares, so they're fixed here before go-live:
- **Database library:** drizzle-orm 0.44 → **0.45.3**. The old version has high advisory GHSA-gpj5-g38j-94v9 (SQL
  injection through identifiers). The tool never builds identifiers from input, so it wasn't exploitable, but the fix was one line.
- **Cross-site guard:** `hono/csrf` on `/api`. Before this, another website could make a signed-in salesperson's
  browser send a form post, an upload or a delete to the tool. Those now get 403; the tool's own requests still pass
  (checked in a real browser, including the photo upload).
- **Error logs:** a failed database query used to log the query's values (a salesperson's email and contact details).
  `safeErrorLine()` now keeps only the database's reason, for the error handler and all four daily jobs.
- **Dependency floors:** `sharp` and drizzle-kit's `esbuild` are pinned above advisories, and every package is on vitest
  4.1.11. `pnpm audit` is clean. All are test and dev tools only.
- **Proof:** 233 tests (+6 in `test/security.test.ts`, each mutation-checked); typecheck and web build clean. A live
  local Worker refused cross-site writes and logged only "database query failed: … no such table". Render is untouched,
  so `diff-reference` is not affected.
- **Goes live with the next deploy** (Matt's click). No data or config changes.
