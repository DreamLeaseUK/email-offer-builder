## 2. Decisions made since the brief was written

All dated 14 Sept 2026 unless noted.

- **Workers Paid plan** confirmed by Matt but not yet switched on in the dashboard (no card to hand). Free plan is fine until step 3.
- **No MJML.** The v4 Claude Design file is hand-built email HTML; `packages/render` reproduces it as TypeScript template functions. `MARKUP_VERSION` pins what Emma approved.
- **Layout is per campaign** (`Campaign.layout`, `auto | single | stack | grid2 | grid3`), not per template. Auto: 1 → single, 2 → grid2, 3 → stack, 4+ → grid2. grid3 only when chosen; the first review found it small.
- **Email width 640px**, fluid container `width:100%; max-width:640px`, with the standard `[if mso]` 640 ghost wrapper around the whole email. Widened from the design's 600 after the first Outlook review.
- **Badges are orange `#FF8811`** (Matt, 11 Sept), one row per card, capped at 3 / 2 / 2 / 1 for hero / stack / grid2 / grid3.
- **Brochure link under the button** on every card, not beside it. The two 14px brochure glyphs are deliberately deferred.
- **Rounded buttons and badges in classic Outlook use VML** in the exact construction proven by `packages/render/scripts/diag-vml.ts` variant V4. Do not add line-height inside them.
- **No `[if mso]` ghost tables inside the body.** Classic Outlook unwraps conditional comments when it sends or forwards, so ghost grids reached phones as two fixed columns squeezed to fit, and New Outlook's sanitiser leaves stray boxes at comment boundaries. Only the outer 640 wrapper remains.
- **Floated tables (`align="left"`) for the grid were tried and rejected** (`scripts/diag-grid.ts` G3). They fixed New Outlook desktop but Word does not float them, so classic Outlook showed a narrow card in a wide column.
- **Grid units are inline-block divs** with `width:100%; max-width:<cell>px`, wrapped to one column on phones by a media query and by natural wrapping. Card rows are given equal heights via fixed-height cells (badges, derivative, spec line, small print) because New Outlook strips `vertical-align`.
- **Word rules learned** (all in CLAUDE.md): no `mso-padding-alt:0`, no `text-transform`, no inline-block tables, borders on cells not tables, spacing as cell padding or white cell borders (never margins or spacer cells), eyebrows and compliance title upper-cased in code.

## 4. Open issues, in priority order

1. **Classic Outlook grid2 renders a narrow card.** Appeared after the last two changes (content-sized grid badges, `table-layout:fixed` on unit and card tables). The earlier inline-block build rendered one full-width card per row in Word. Suspect `table-layout:fixed`; not proven.
2. **New Outlook desktop narrow pane: image doesn't fill a full-width card.** The `<img width="284">` attribute wins over `width:100%` there. Options: a media-query class, or accept a centred 284px image when a card is alone in a row. Not decided.
3. **New Outlook desktop narrow pane: stack layout wraps image above content** because 250 + 340 doesn't fit the pane. Acceptable degradation, or drop the image column to 220 + content to 370 to give slack. Not decided.
4. **New Outlook desktop wide pane** has not been re-verified since the ghost tables were removed and the equal-height rows added.
5. Brochure glyph icons deferred. Hosted page is currently the email markup in a page wrapper; the full design-system hosted page from brief §7.1 is still owed by Claude Design, as are the tool screens and the one-page guide.
6. Cosmetic: New Outlook desktop scales the whole email down in a pane narrower than 640px. Standard behaviour, leave.

## 5. How to work on the template from here (lesson of 14 Sept)

Eleven builds went out in one day. The ones that stuck were the ones chosen by a side-by-side diagnostic looked at in the real client; the ones that failed were single-screenshot guesses. Rule for the next session:

1. Do not change `packages/render/src/cards.ts` in response to one screenshot.
2. Build a diagnostic `.eml` (see `scripts/diag-vml.ts` and `scripts/diag-grid.ts` for the pattern) that uses the **real** card with badges, in each candidate construction, labelled.
3. Have Matt open it in classic Outlook, New Outlook desktop (wide and narrow pane), and forward it from New Outlook to the phone (Outlook and Gmail). Collect all results before choosing.
4. Apply exactly the winner, regenerate the fixtures (`pnpm --filter @offer-mailer/render fixtures`), deploy, and send Matt the `.eml` files for a full pass.

Test files are produced by `packages/render/scripts/write-fixtures.ts` into `packages/render/out/` (git-ignored). `.eml` files carry `X-Unsent: 1` so classic Outlook opens them as sendable drafts.

**Diagnostic sent 14 Sept (`scripts/diag-card.ts`), awaiting Matt's results.** Three emails so none is clipped by Gmail on the phone forward:

- `diag-card-grid.eml`: ruler bars 286/302/320 for Word, then D1 current build, D2 without `table-layout:fixed`, D3 with `table-layout:fixed` moved into an `@media screen` rule (Word skips it), D4 = D2 with the two longest badges (overflow test), D5/D6 Word-only controls with the old 104px badge minimum. Expected cause of the narrow Word card: `table-layout:fixed` makes Word freeze the frame's column at content width (284 image + 36 padding ≈ 320) instead of resolving `width="100%"`; the badge change only alters what that frozen width is. Prediction: D2, D3, D6 full width in Word; D1, D5 narrow, matching the 320 bar.
- `diag-card-image.eml`: single grid2 card with a pink image cell. I1 current, I2 class + media query `!important`, I3 inline `!important`, I4 no width attribute (CSS px; may blow up in Word, that is the test), I5 `min-width:100%`, I6 unit unlocked by `max-device-width` so a narrow desktop pane keeps a centred 284px card instead of stretching.
- `diag-card-stack.eml`: S1 current, S2 real two-cell row (needs the classic Outlook forward test, Word exports real rows with absolute widths), S3 percentage units.

Side finding: `pill()` emits an invalid `min-width:-Npx` on every content-sized pill (grid badges, hero and stack buttons). Browsers drop it; fix it with the winner. Badges are capped by count only; with `config/badges.json` the worst grid2 pair is ~314px in a 246px row, which is the likely reason `table-layout:fixed` was added. The fix should cap by estimated width so the row can never exceed the card in any client.
