## 2. Decisions made since the brief was written

All dated 14 Sept 2026 unless noted. The morning's template decisions below (width 640, badge caps, VML pills, no body ghost tables, inline-block div units, the Word rules) were superseded that afternoon by the v5 reference, recorded further down; they are kept for history.

- **Workers Paid plan** confirmed by Matt but not yet switched on in the dashboard (no card to hand). Free plan is fine until step 3.
- **No MJML.** The v4 Claude Design file is hand-built email HTML; `packages/render` reproduces it as TypeScript template functions. `MARKUP_VERSION` pins what Emma approved.
- **Layout is per campaign** (`Campaign.layout`, `auto | single | stack | grid2 | grid3`), not per template. Auto: 1 → single, 2 → grid2, 3 → stack, 4+ → grid2. grid3 only when chosen; the first review found it small.
- **Email width 640px**, fluid container `width:100%; max-width:640px`, with the standard `[if mso]` 640 ghost wrapper around the whole email. Widened from the design's 600 after the first Outlook review.
- **Badges are orange `#FF8811`** (Matt, 11 Sept), one row per card, capped at 3 / 2 / 2 / 1 for hero / stack / grid2 / grid3.
- **Brochure link under the button** on every card, not beside it. The two 14px brochure glyphs are deliberately deferred.
- **Rounded buttons and badges in classic Outlook use VML** in the exact construction proven by `packages/render/scripts/diag-vml.ts` variant V4. Do not add line-height inside them.
- **No `[if mso]` ghost tables inside the body.** Classic Outlook unwraps conditional comments when it sends or forwards, so ghost grids reached phones as two fixed columns squeezed to fit, and New Outlook's sanitiser leaves stray boxes at comment boundaries. Only the outer 640 wrapper remains.
- **Floated tables (`align="left"`) for the grid were tried and rejected** (`scripts/diag-grid.ts` G3). They fixed New Outlook desktop but Word does not float them, so classic Outlook showed a narrow card in a wide column.
- **Grid units are inline-block divs** with `width:100%; max-width:<cell>px`, wrapped to one column on phones by a media query and by natural wrapping. Card rows are given equal heights via fixed-height cells (badges, derivative, spec line, small print) because New Outlook strips `vertical-align`.
- **Word rules learned** (superseded that afternoon, see below): no `mso-padding-alt:0`, no `text-transform`, no inline-block tables, borders on cells not tables, spacing as cell padding or white cell borders (never margins or spacer cells), eyebrows and compliance title upper-cased in code.

Step 3 (14 Sept, afternoon):

- **The offer page is not fully server-rendered.** Identity, the four slugs, headline stats, quick-spec, processing fees and the default configuration are in the HTML (`window.motorleaseInit` plus a few elements). Prices, initial payment and the badge flags are loaded by the page's Vue component from `GET /api/carresults/GetOfferDropdownsForCar?...` (same origin, no auth). The `url` adapter therefore fetches the page (HTMLRewriter for identity and the image URL) and then that JSON endpoint for the configuration's price, options and flags. The JSON-LD `lowPrice` is kept only as a cross-check (the site's JSON-LD has an unbalanced brace, so it is read with a regex).
- **Initial payment is derived** the way the site does it: initial months × monthly (plus maintenance when included). The endpoint's `initialPayment` field is 0.
- **Term, mileage and initial-payment chips come from the endpoint's option lists**, not a hard-coded set; they are returned alongside the offer and cached with it.
- **CAP ID surfaces in two places**: the image URL (as before) and the endpoint's `rateBookIdentifier` (`cars-<capId>-p-12-48-6000-n`). The parser maps named fields only; tests assert the fixture's CAP ID digits never reach an Offer, the cache row or the API response. Test fixtures are the real pages with the image host replaced and the CAP ID zeroed.
- **Badges from the site**: `specialOffer` → hot badge "Special offer"; `isInStock` → "In stock"; the site's free-text tags map onto the fixed list by alias (e.g. "Limited Stock" → "Limited numbers"); anything not on the list is dropped. `stock` is `in_stock` / `limited` / unset.
- **Images**: Cloudflare Images binding (`TRANSFORM`) → 1200px-wide JPEG at quality 82 on white, stored as `vehicles/<sha256>.jpg`, served at `/f/vehicles/<sha>.jpg` with immutable caching. The site's images are 750px wide, so the stored copy is 750×500 (Images does not upscale); sharp at card size, slightly soft on a retina hero. A failed image is a warning, not a failed lookup.
- **Cache**: D1 `lookup_cache`, keyed by the canonical URL (contract type, slug, explicit configuration; tracking parameters dropped), 24 hours, holding the parsed result (offer + options), never HTML.
- **Brochures**: `POST /api/brochures/ensure` (stored → harvest → 404 for upload/paste), `POST /api/brochures/manual` (URL or multipart PDF), `GET /api/brochures/current`, public `GET /b/<id>` (serves our PDF inline, or redirects to the manufacturer's request page), `GET /f/brochures/<sha>.pdf`. Superseded copies keep serving. Harvest is search → allowlisted page scrape → manufacturer-site map, 15-credit cap, UK check by domain upgraded to content when the first two pages show £ or OTR and no €.
- **Tests**: `packages/adapters` under plain vitest with the wasm HTMLRewriter; `apps/api` under `@cloudflare/vitest-pool-workers` (vitest 4 in that package only) with real local D1, R2 and Images bindings. The pool's workerd trails wrangler's by a fortnight, so `vitest.config.ts` pins the test compatibility date; bump it with the wrangler one.
- **`pnpm deploy` is pnpm's own command**; the script is `pnpm run deploy`.

## 5. How to work on the template from here

The markup is no longer the code's own invention: `design/dreamlease-offer-mailer-v5.html` is the source of truth and `packages/render` reproduces it. Rules:

1. After any change to `cards.ts` or `render.ts`, run `pnpm --filter @offer-mailer/render exec tsx scripts/diff-reference.ts`. It renders each layout, strips data (text, href, src, alt), and diffs the tag-and-attribute structure of every section against the reference. Any difference that is not data is a deviation and must be justified in the header of `cards.ts`. Current knowing deviations: logo 98px wide (the asset is 196px, 99 would distort it); the salary-sacrifice price blocks and the red "View this offer" link, which the reference does not show but its brief requires.
2. Do not patch a construction in response to one screenshot. If a client shows a fault, build a labelled diagnostic `.eml` with the real card in each candidate construction (`scripts/diag-vml.ts` and `scripts/diag-grid.ts` show the pattern), have Matt check it in classic Outlook, New Outlook desktop (wide and narrow pane) and on his phone via a New Outlook forward, collect all results, then change the reference and the code together.
3. Regenerate the fixtures (`pnpm --filter @offer-mailer/render fixtures`), deploy (`pnpm run deploy`), and send Matt the `.eml` files from `packages/render/out/` for a full pass.

Test files are produced by `packages/render/scripts/write-fixtures.ts` into `packages/render/out/` (git-ignored). `.eml` files carry `X-Unsent: 1` so classic Outlook opens them as sendable drafts.

History, for context only: eleven builds went out on 14 Sept before the v5 reference arrived, each reacting to one screenshot; the constructions they settled on (no body ghost tables, VML pills, 640px, min-width pills) are superseded by the reference and the diagnostic that was testing them was withdrawn.
