  - the **tool** goes on `marketingtools.dreamelectric.uk` (Matt: the tool can be on dreamelectric; it is staff-only

    customers"), attached as a Cloudflare for SaaS custom hostname on the `dreamelectric.uk` zone. GoDaddy keeps
    DreamLease's DNS; `www`, email and MotorComplete's records are untouched. One hostname is inside the free 100.
  - The MotorComplete password test site on `dreamelectric.uk` is not needed (Matt). Nothing here depends on it, so
    it is left alone.
- **Compliance approver:** "Emma alone edits and approves" (my recommendation, accepted with "go"). A deputy can be
  added at runtime with `COMPLIANCE_EMAILS`, without a code change.

  on the first route's zone, and a `--host` override must itself be a zone on the account (workers.dev is not). Its
  `triggersDeploy` publishes routes and custom domains only when the file lists some, so dashboard-made ones survive
  every deploy. Removed; `dev:live` recovered (0.6.0, `/api/me` 200).
- **Correction to my own mid-session note:** I recorded that uploads through the Vite proxy failed the cross-site
  guard (403). In a browser they do not: `hono/csrf` also accepts the browser's `Sec-Fetch-Site: same-origin`, and a
  multipart POST from `localhost:5173` passed (404 from an unknown route, not 403). The 403 came from a test client
  that sends no such header. The proxy change I built for it was removed.

## 8. Gotchas (new)

- **Never put `routes` in `wrangler.jsonc`** while `dev:live` is in use: it silently serves production instead of the
  local code.
- **`dev:live` does not serve `/app/`**: it runs at Cloudflare's edge, so it is not "this laptop". Use the Vite app
  (5173) for work and `api-local` (8788) to check the served build.
- **Create the Access application before the Custom Domain**, so `marketingtools.` is protected from its first
  request.
- **`ACCESS_AUD` secret after the deploy, never before:** a var and a secret cannot share a name, and the old empty
  var is removed only by the deploy of this config.
