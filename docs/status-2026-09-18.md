# DreamLease Offer Mailer — status and build log (session 4)

Last updated: 18 September 2026. **This is the current-state build log.** `status-2026-09-16.md` (session 3) and earlier
are history. The technical map is `architecture.md`; the brochure design and its evidence are in
`brochure-finder-brief.md`; the four rules and the working method are in `CLAUDE.md`.

## 1. Headline
The brochure allowlist is gone. Brochure discovery is now an automatic **finder**: it discovers the manufacturer's
official UK site, reads the links on its brochure / downloads / model pages, and attaches a document only after
reading it. The rep never picks from a list. Built, tested (**172 tests**: schema 18, adapters 64, render 31, api 59),
proven live through `wrangler dev`, and **deployed — production Worker is v0.4.0** (D1 migration `0002` applied).
Production `/api` still answers **503 until Cloudflare Access exists**, so the interface is tested at
`http://localhost:5173`.

## 2. How the design changed from the brief (Matt's decisions, 17–18 Sept)
- **No picking.** The brief's "machine finds, rep confirms a candidate list" was dropped: the machine finds and
  verifies; if it is not sure it attaches nothing and says why.
- **Web brochures count.** About a third of manufacturers publish no PDF (VW, Jaecoo, Vauxhall's current guide).
  The manufacturer's own UK web brochure is accepted and linked ("View brochure").
- **Six outcomes, document type kept separate.** `verified_pdf`, `verified_web_brochure`, `official_page_only`,
  `brochure_request`, `not_verified`, `search_failed`, plus `documentType` (`brochure` | `price_spec_guide`).
  Only the first two attach by themselves. An official page or a request form is offered to the rep as a one-click
  accept. A price page is never auto-attached (Volvo's `/pricelists/` hub is why).
- **Age limits:** 12 months for a brochure, 6 for a price & spec guide; the newest of the text date and the URL date;
  re-checked every time a stored document is attached.
- **"Not found" is auditable.** Every search keeps a trace (queries, pages opened, every document and why it was
  dropped). Nothing-found is remembered 7 days; a search that failed is never remembered and offers a retry.
- **Never work around a download protection** (Leapmotor's storage refuses everyone → `official_page_only`). A public
  PDF behind a lead form (MG) is still `verified_pdf`, flagged `lead_capture_present`.
- **No promotions-register change** for brochures (Matt).
- **Parked until after launch:** a Claude skill (Firecrawl + Playwright) that builds a brochure library in batch,
  with these checks as its gate. See §5.

## 3. What was built (branch `brochure-finder`, 3 commits + version bump)
- `packages/adapters/src/brochure/finder.ts` — the finder (pure; Firecrawl and HTTP injected). `harvest.ts` retrieves
  and stores a verified PDF (direct, then Firecrawl `rawBase64`), records a web brochure, and converts an accepted
  official page / request form. `ensure.ts` — stored / fresh / stale / none, remembered negatives, age re-check.
  Removed: `allowlist.ts`, `config/manufacturer-uk-domains.json`, `scripts/audit-allowlist.mjs`.
- `packages/schema` — `BrochureKind` gains `web`; `documentType`, `editionDate`, `finder`; `BrochureSearch` (the trace).
- `apps/api` — `/brochures/ensure` always 200 `{ state, brochure?, search?, remembered? }` (+ `force`);
  `/brochures/accept`; manual paste falls back to `rawBase64`; `/b/:id` redirects `web` as well as `gated`; table
  `brochure_searches` (migration `0002`); the daily Cron supersedes a linked brochure whose page is now 404/410.
- `packages/render` — labels only: "View brochure", "View price & spec guide", "Download price & spec guide (PDF)".
  v5 markup and `MARKUP_VERSION` untouched (`diff-reference`: the same 8 pre-existing logo-width lines before and after).
- `apps/web` — new brochure control: staged progress, what was attached and from where with "Open it to check",
  "Wrong? Replace it", "Search again"; amber nothing-found panel (what we checked, search the web, official site,
  upload / paste, accept official page, send without); red search-failed panel with "Try again".

## 4. Evidence
- **Proof runs (throwaway script, before the port):** 10 tuned models → 22-case regression suite **20/22 status,
  21/22 document type, zero wrong attachments**; a fresh blind set of 10 → **4/10 status, one wrong attachment**
  (Volvo's pricelists hub page, now fixed by never auto-attaching a price page) and five misses caused by official
  asset hosts the rules did not recognise (`mazda.eu`, `cupraofficial.co.uk` now recognised; `contentstack.com`-style
  CDNs only when linked from the official page). Hand-checked ground truth for all 32 models, the preserved blind
  outputs and the frozen scripts are in `C:\Users\MatthewWilson\.claude\tmp-finder\`.
- **Replay tests:** 12 of those models run in the adapter tests from recorded Firecrawl responses (zero credits).
- **Live, through the real Worker (`wrangler dev`, 18 Sept):** Kia EV2 → PDF stored in R2 (3.9 MB, 6 s, 10 credits) and
  served from `/b/:id`; Jaecoo 7 → web brochure, `/b/:id` 302s to it; Leapmotor C10 → `official_page_only`; Denza Z9 GT →
  `not_verified`; BYD Seal in the interface → price & spec guide PDF attached in 7 s, email preview shows
  "Download price & spec guide (PDF)".
- **Honest limit:** the rules generalise worse than the regression suite suggests. Expect a meaningful share of
  "nothing attached" on brands not yet seen; each one is visible in the trace, and an upload fixes that model for
  every rep for 90 days.
